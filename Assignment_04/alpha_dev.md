# Differences
    Immediately they are using RL to discover new algorithms and optimize the code for these algorithms. They are trying to optimize the code's world through RL. They begin optimizing assembly code for the cpu. The argument as to why assembly optimizations are smarter than C++ is because they can find more optimizations that may not be as intuitive in C++. This project therefore is not really only for sorting its a way of optimizing existing algorithms in general. Sorting algorithms was chosen because it's a concept that has been rooted deeply in human history for a long time and very relevant today still. They state that sorting algorithms are used trillions of times every day and therefore library access to it would help many programs. 

    They use RL for this by turning the state space of the coding world into an "assembly game". It starts with an empty buffer and slowly must generate the algorithm. The state space is therefore the current assembly code that is present. The action space is assembly instructions. The reward is a combination of how correct the algorithm is and also how fast it is in performing its desired outcome. AlphaDev receives state and then action then adds it to its past state to make the new state for the next choice. After the program is correct it begins to optimize for latency. Some programs have correlations between length and latency and therefore you can use code length as a proxy for latency, If there are branches like if else statements then the correlation goes away and therefore you must use actual measured latency. They measured the time taken using the cpu performance counter. 


    The way the actual algorithm is made to work is that they basically trained a transformer to encode meaning about assembly code, another neural network to create embeddings about cpu registers and memory, then a value function for future prediction latency that uses a concatenation of both the latent vectors of the transformer and network. Then they do a tree search down possibilities to figure out what potential routes should be explored. They pick an outcome and compare the prediction vs the actual latency time / their function that can approximate latency depending on the code and keep going until it gets better. I believe it is end to end learning and everything is trained together. 

# Significance
    The fact they are able to use RL to try and optimize code by figuring out its future value has several very interesting potential outcomes. Something they suggested was using LLMs and RL together which is probably most definitely being used today actually to optimized code and general output quality. They also talk about codesigning hardware and software together with RL which could also have crazy optimization implications. Basically, the fact that this end to end learning worked means that there are several ways they can build on what already exists / create new foundations to build off on Also the way they suggested LLMs to have RL piled on top is kind of eery because it is very representative of what the current SOTA is.
